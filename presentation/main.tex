\section{Neural Networks and the Matrix Multiplication}
\begin{frame}
  \frametitle{Basic Neural Net (MLP/FFN)}
  \centering
  \only<1>{
    \resizebox{0.8\textwidth}{!}{\input{../assets/figures/nn_0}}
  }
  \only<2>{\resizebox{0.8\textwidth}{!}{\input{../assets/figures/nn_1}}
    \[y_1 = x_1 w_{11} + x_2 w_{12} + x_3 w_{13} + x_4 w_{14}\]
  }
  \only<3>{\resizebox{0.8\textwidth}{!}{\input{../assets/figures/nn_2}}
    \[y_2 = x_1 w_{21} + x_2 w_{22} + x_3 w_{23} + x_4 w_{24}\]
  }
  \only<4>{\resizebox{0.8\textwidth}{!}{\input{../assets/figures/nn_3}}
    \[y_3 = x_1 w_{31} + x_2 w_{32} + x_3 w_{33} + x_4 w_{34}\]
  }
  \only<5>{\resizebox{0.8\textwidth}{!}{\input{../assets/figures/nn_4}}
    \[y_4 = x_1 w_{41} + x_2 w_{42} + x_3 w_{43} + x_4 w_{44}\]
  }
\end{frame}

\begin{frame}
  \frametitle{Linear Algebra Interpretation}
  Here, notice that for each \(y_i\), we are taking a weighted sum of the
  \(x\) elements. That is,

  \[y_i = x_1 w_{i1} + x_2 w_{i2} + x_3 w_{i3} + x_4w_{i4}.\]

  Arranging the \(y_i\) into a vector, we get

  \[
    \begin{bmatrix}
      y_1 \\ y_2 \\ y_3 \\ y_4
    \end{bmatrix}
    =
    \begin{bmatrix}
      w_{11} & w_{12} & w_{13} & w_{14} \\
      w_{21} & w_{22} & w_{23} & w_{24} \\
      w_{31} & w_{32} & w_{33} & w_{34} \\
      w_{41} & w_{42} & w_{43} & w_{44}
    \end{bmatrix}
    \begin{bmatrix}
      x_1 \\ x_2 \\ x_3 \\ x_4
    \end{bmatrix}.
  \]

\end{frame}

\begin{frame}
  \frametitle{Linear Algebra Interpretation}
  We can generalize the number of \(x\)'s and the number of \(y\)'s.

  \[
    \begin{bmatrix}
      y_1 \\ y_2 \\ \vdots \\ y_m
    \end{bmatrix}
    =
    \begin{bmatrix}
      w_{11} & w_{12} & \cdots & w_{1n} \\
      w_{21} & w_{22} & \cdots & w_{2n} \\
      \vdots & \vdots & \ddots & \vdots \\
      w_{m1} & w_{m2} & \cdots & w_{mn}
    \end{bmatrix}
    \begin{bmatrix}
      x_1 \\ x_2 \\ \vdots \\ x_n
    \end{bmatrix}.
  \]

  We say, \(n\) is the \emph{input dimension} and \(m\) is the \emph{output dimension}.
\end{frame}
\begin{frame}
  \frametitle{Computing with multiple \(x\) vectors.}
  Suppose we have multiple \(x\) vectors, for which we want to pass through our
  neural network. We can stack the multiple \(x\) vectors in the \textbf{batch},
  which we compute with a matrix multiplication.

  \[
    \resizebox{\textwidth}{!}{$\displaystyle
      \begin{bmatrix}
        y_1^{(1)} & y_1^{(2)} & \cdots & y_1^{(B)} \\
        y_2^{(1)} & y_2^{(2)} & \cdots & y_2^{(B)} \\
        \vdots & \vdots & \ddots & \vdots \\
        y_m^{(1)} & y_m^{(2)} & \cdots & y_m^{(B)}
      \end{bmatrix}
      =
      \begin{bmatrix}
        w_{11} & w_{12} & \cdots & w_{1n} \\
        w_{21} & w_{22} & \cdots & w_{2n} \\
        \vdots & \vdots & \ddots & \vdots \\
        w_{m1} & w_{m2} & \cdots & w_{mn}
      \end{bmatrix}
      \begin{bmatrix}
        x_1^{(1)} & x_1^{(2)} & \cdots & x_1^{(B)} \\
        x_2^{(1)} & x_2^{(2)} & \cdots & x_2^{(B)} \\
        \vdots & \vdots & \ddots & \vdots \\
        x_n^{(1)} & x_n^{(2)} & \cdots & x_n^{(B)}
      \end{bmatrix}.
    $}
  \]

  We write this succinctly as \(Y = WX\), where \(Y \in \mathbb{R}^{m \times B}\),
  \(X \in \mathbb{R}^{n \times B}\), and \(W \in \mathbb{R}^{m \times n}\).

  \begin{alertblock}{Yippee!}
    We have successfully mapped the batched computation of a \textbf{linear layer}
    a matrix multiplication!
  \end{alertblock}
\end{frame}

\begin{frame}
  \frametitle{Composing Layers}

  We can view \(W\) as a function that takes in an \(n\)-dimensional vector and
  maps it to an \(m\)-dimensional vector. \(W \colon \mathbb{R}^n \rightarrow \mathbb{R}^m\).
  We create deep neural networks by \emph{composing} these transformations, along
  with  \textbf{nonlinearities} \(\sigma_i\).

  \input{../assets/figures/layer_composition}

  \begin{block}{Remark}
    Notice that this figure doesn't show the \emph{batch} dimension. However,
    if you work through the dimension mappings, the \emph{batch} dimension \(B\)
    will be unaffected by this composition.
  \end{block}
\end{frame}

\begin{frame}
  \frametitle{Limitations for Neural Network Architecture}

  \input{../assets/figures/layer_composition}

  Architectures such as \textbf{Transformers} and \textbf{CNNs} have connectivity
  patterns more complex than a simple composition of layers. Nevertheless, linear
  transformations remain a fundamental computational primitive in neural network
  architectures.

  \begin{block}{A fundamental building block}
    A linear transformation may seem like a narrow operation to study, but modern
    neural networks perform it repeatedly and at enormous scale. Its efficiency
    therefore has an outsized effect on training and inference performance. The
    rest of this presentation explores the hardware and techniques that make these
    operations efficient.
  \end{block}

\end{frame}

\begin{frame}
  \frametitle{Takeaways}
  \begin{enumerate}
    \item A linear layer applied to a batch of inputs can be expressed as a single
      matrix multiplication, \(Y = WX\).
    \item Deep networks compose these linear transformations with nonlinearities.
      More complex architectures change how layers are connected, but linear
      transformations remain a fundamental building block.
    \item \textbf{Matrix multiplication therefore captures a large and reusable part of
      neural network computation.}
  \end{enumerate}

  \begin{alertblock}{Why is this representation useful?}
    It separates what the network computes from how the hardware executes it.
    Instead of optimizing every architecture from scratch, we can focus on one
    common computational primitive. Next, we will examine how GPUs execute matrix
    multiplications efficiently.
  \end{alertblock}
\end{frame}

\section{Why GPUs?}

\begin{frame}
  \frametitle{From graphics pipeline to AI accelerator}
  \begin{itemize}
    \item \textbf{1999---2003:} fixed-function graphics gives way to programmable
      vertex and pixel shaders.
    \item \textbf{2004:} Brook for GPUs demonstrates a high-level stream-programming
      model on top of graphics APIs.
    \item \textbf{2006---2007:} GeForce 8800 introduces a unified shader architecture;
      NVIDIA releases CUDA publicly in 2007.
    \item \textbf{2010:} Fermi adds a coherent cache hierarchy, ECC support, and much
      stronger support for C++ and scientific computing.
    \item \textbf{2017:} Volta introduces Tensor Cores for mixed-precision matrix
      multiply--accumulate.
    \item \textbf{2020---2024:} Ampere broadens Tensor Core formats; Hopper adds the
      FP8 Transformer Engine; Blackwell adds further low-precision and AI-specific hardware.
  \end{itemize}
\end{frame}

\begin{frame}
  \frametitle{Demand for 3D graphics}
  GPU's came about due to the increase in computational power needed to render
  3D games in real time. This requires \emph{millions} of FLOP's per second.
  CPU's could not keep up.
\end{frame}
\begin{frame}
  \frametitle{Parallelism}
  Rendering graphics has a nice property that we can take advantage of:
  \textbf{parallelism}.

  Each pixel on the screen doesn't really care any of the other pixels. Furthermore,
  the computation that is required for each pixel isn't that complex either.
  The difficulty in rendering graphics is the volume of computations.

\end{frame}

\begin{frame}
  \frametitle{Computing a Matrix Multiplication}
  Let \(A\) and \(B\) be two \(4\times4\) matrices. The matrix multiple \(C = AB\)
  results in another \(4\times4\) matrix.

  \includegraphics[width=\linewidth]{matmul.png}

  The operations are very simple, but the number of operations grow on the order
  of \(\mathcal{O}(n^3)\), where \(n\) is the dimensions of the matrices.

  \begin{block}{Remark}
    Linear algebra and matrix multiplications show up everywhere in scientific
    computing, so computing them efficiently has always been in high demand.
  \end{block}
\end{frame}

\begin{frame}
  \frametitle{Matrix Multiplication is Parallel}

  Each element of the output is independent. The results of \(C_{11}\) does not
  effect the results of \(C_{12}\), or any other element.

  \begin{block}{Remark}
    If matrix multiplication is a \textbf{parallel} task, and GPU's were designed for the
    \textbf{parallel} task of rendering graphics, can we repurpose GPU's to do matrix multiplication?
    \pause (Yes.)
  \end{block}
\end{frame}

\section{Optimizing \textbf{Ge}neral \textbf{M}atrix \textbf{M}ultiplication (GEMM) on CUDA}
\begin{frame}
  \frametitle{Why GEMM?}
\end{frame}

\begin{frame}
  \frametitle{Closer look at CUDA}
  \begin{itemize}
    \item A CUDA \textbf{kernel} specifies the program.
    \item All \textbf{threads} run the the same kernel on different data.
    \item Threads are grouped into \textbf{blocks}. Blocks are assigned to SM's .
    \item Threads in the same block have access to a \textbf{shared memory} pool.
    \item Efficiently using shared memory is crucial to efficient kernels.
  \end{itemize}

  \begin{itemize}
    \item Blocks and threads are identified through \textbf{indexes}.
    \item Kernels use indexes to define how to delegate work between threads.
    \item \textbf{Host} code controls top level logic and \textbf{launches} kernels, specifying how many blocks/threads are needed.
  \end{itemize}

\end{frame}

\begin{frame}[fragile]
  \frametitle{Naive SGEMM}

  \begin{lstlisting}[basicstyle=\ttfamily\tiny]
__global__ void sgemm_naive(int M, int N, int K, float alpha, const float *A,
                            const float *B, float beta, float *C) {
  const uint x = blockIdx.x * blockDim.x + threadIdx.x;
  const uint y = blockIdx.y * blockDim.y + threadIdx.y;

  if (x < M && y < N) {
    float tmp = 0.0;
    for (int i = 0; i < K; ++i) {
      tmp += A[x * K + i] * B[i * N + y];
    }

    C[x * N + y] = alpha * tmp + beta * C[x * N + y];
  }
}

void run_sgemm_naive(int M, int N, int K, float alpha, float *A, float *B,
                     float beta, float *C) {
  dim3 blockDim(32, 32);                          // Common Block size.
  dim3 gridDim(CEIL_DIV(M, 32), CEIL_DIV(N, 32)); // How many blocks to cover C
  sgemm_naive<<<gridDim, blockDim>>>(M, N, K, alpha, A, B, beta, C);
}

int main() {
  // ... set up matrices and dimensions ...
  run_sgemm_naive(M, N, K, alpha, A, B, beta, C);
}
  \end{lstlisting}

\end{frame}
